### 🎯 Business Challenge

A hypothetical organization relies on manual employee onboarding processes involving spreadsheets, email approvals, and manually provisioned IT accounts.

This workflow creates risks involving incomplete information, approval delays, manual rework, and limited operational visibility.

### 🛠️ Hands-On Activities

- Developed an AS-IS employee onboarding process map using Lucidchart.
- Designed a proposed TO-BE workflow with validation, approval routing, API integration, and exception handling.
- Executed GET and POST requests using Postman.
- Inspected JSON request payloads and API responses.
- Created automated Postman response assertions.
- Documented successful UAT results in Jira.
- Created a simulated email-validation defect.
- Linked the simulated defect to its related UAT ticket.
- Prepared business decision and implementation documentation.

### 🗺️ AS-IS — Manual Employee Onboarding

![AS-IS Manual Employee Onboarding](Employee_Onboarding_SaaS_Implementation/00_Evidence/Actual_Exports/Process_Maps/01_AS_IS_Manual_Employee_Onboarding_Process.png)

**Current-state scenario:** HR information entry, manager approvals, email handoffs, and manual IT provisioning.

### 🟢 TO-BE — Proposed Automated Onboarding

![TO-BE Automated Employee Onboarding](Employee_Onboarding_SaaS_Implementation/00_Evidence/Actual_Exports/Process_Maps/02_TO_BE_Automated_Employee_Onboarding_Process.png)

**Future-state design:** Structured employee intake, validation, manager approval, secure API orchestration, identity provisioning, exception routing, and auditability.

## 🏗️ From Business Requirements to Working Software

This repository includes a locally implemented Python/SQLite application connecting business analytics, KPI reporting, requirements management, UAT tracking, and structured gap analysis.

### ⚙️ Application Capabilities

| Capability | Function |
|---|---|
| 📊 Six SQL-Backed Dashboards | Business performance reporting |
| 🔎 Interactive Filtering | KPI exploration |
| 📂 Source Data Drilldown | Analytical investigation |
| 📋 Requirements Management | Requirement tracking |
| 🧪 UAT Management | Acceptance testing records |
| 🔍 Gap Management | Process gap tracking |
| 👥 Role-Based Access | Viewer, Analyst, Reviewer, Administrator |
| 🛡️ Audit History | Workflow activity records |
| 🔄 Data Refresh | Staged validation and replacement |
| 💾 Persistent Storage | SQLite database |

### 🏛️ Application Architecture

```mermaid
flowchart TD
    A[Business Users] --> B[Browser Interface]
    B --> C[Python Application API]
    C --> D[Analytics Services]
    C --> E[Business Analysis Workflows]
    D --> F[SQL Dashboards]
    E --> G[Requirements and UAT]
    F --> H[(SQLite)]
    G --> H
    C --> I[Access Controls and Audit History]
```

### ▶️ Run the Application Locally

**Requirements:** Python 3.10+ and SQLite 3.25+.

```bash
git clone https://github.com/JamieChristian22/business-analyst-portfolio.git
cd business-analyst-portfolio
python3 Local_System/server.py
```

Open `http://127.0.0.1:8765`.

### 🧪 Run Integration Tests

```bash
python3 Local_System/test_system.py
```
